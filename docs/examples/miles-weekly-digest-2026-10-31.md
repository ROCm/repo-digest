# miles Weekly Digest - 2026-10-31

## Summary
This week landed a wave of **breaking configuration and API changes**. `parse_args` now returns a validated Pydantic `AllConfig` that rejects unknown fields. Custom hooks and `--custom-*-path` options now take typed configs, and **Megatron** train, save and load calls take explicit configs. `--router {sglang,miles}` replaces `--use-miles-router`, and `--rollout-shuffle` is now on by default. **LoRA** support grew: **torchtitan** LoRA syncs adapters to **SGLang**, canonical **MultiLoRA** is now the Tinker default, and DeepSeek-V4.1-Flash and MiMo-V2.6 LoRA were added. Training-correctness fixes cover multi-LoRA gradient accumulation, LR-scheduler double-stepping on **checkpoint** resume, and geometric **TIS** normalization. Among newly submitted issues, a user report (#4469, open) says `--allgather-cp` gives wrong log-probs and NaN grads on stock Qwen3 attention. Three other issues propose features.

- Fix distill_qwen loss mask to keep full prompt context, train EOS, and trim untrainable trailing turns by *Shi-Dong* [1d5243c](https://github.com/radixark/miles/commit/1d5243c3161ab0248f2d59e9ccefce8ee3dfabd8)

    This is a training-correctness fix in `miles/utils/mask_utils.py` for the distill_qwen (DeepSeek-style) path. Earlier turns are now rendered as untrained prompt context, where before only the first message was kept. - Fix multi-LoRA gradient accumulation by syncing each request's gradients separately, then adding them to the retained buffers by *Yueming Yuan* [1f9fdb8](https://github.com/radixark/miles/commit/1f9fdb8d2b69c0833476054bda197b8246346efb)

    Fixes a training correctness bug in the **Megatron** **MultiLoRA** path. Gradients retained across requests could be scaled again when the DDP buckets were re-synchronized, which was most likely to affect expert-parallel gradients. `accumulate_gradients` replaces `reset_grad_metadata_keep_grads`. It snapshots the grad buffers, zeroes them, runs forward/backward, and then adds the snapshot back. On an exception it restores the snapshot, so a failed request leaves the accumulated gradients unchanged. This matters for production multi-policy and per-slot LoRA training that uses `LayerWiseDistributedOptimizer`, which still requires `use_distributed_optimizer=False`. Runs that accumulate gradients over several requests may see different gradient values after this change. The diff contains no ROCm-specific changes.

- Fix Megatron LR scheduler double-stepping on resume unless checkpoint skipped scheduler state by *Alexander Zhipa* [3c91b71](https://github.com/radixark/miles/commit/3c91b7117669bb916942cf7fdd1666bb3a7a5d22)

    Corrects a training-correctness bug in `load_model_state` for the **Megatron** backend. Previously, resuming with `use_checkpoint_opt_param_scheduler=False` re-stepped the scheduler even though MCore had already restored the step count. This skewed the learning rate and weight decay after a **checkpoint** resume. The scheduler is now stepped only when state was not restored: with `no_load_optim`, with a release checkpoint at iteration 0, or when no checkpoint was found. LoRA adapter resumes count as restored. This affects long-running production RL runs that resume after failures or restarts. Tests cover each case. The diff has no ROCm-specific changes.

Rewards for existing runs may shift lower after this change. The tests were extended to cover the new cases. No ROCm-specific impact is evident in the diff.

- Fix geometric **TIS** batch normalization to average over sequences, not tokens, by *Alexander Zhipa* [a14a56b](https://github.com/radixark/miles/commit/a14a56b7fa7e061ed96eb29cccaa2594eaf4c9e1)
